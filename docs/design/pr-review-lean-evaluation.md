## 採点上の注意

#588の説明不整合2件は実行時バグ2件という意味ではない。現行版は別のBB欠落時の説明漏れも指摘しており、leanが全指摘を包含したわけではない。ライブのEVゼロは意図した観測値で、不具合として扱う根拠がない。また以前の評価の合成入力は未完了行へ負の損益を直接渡していたが、実際のmapperでは欠落値から損益0を作る。その例を到達可能な数値バグの証拠にはできない。

#592のpreview経路は既存問題としての言及で、入口2件を新規不具合2件とは数えない。#594現行版の既存rate-limitリスクも、配備全体の防御を確認していない。指摘数をそのまま品質に換算しない。

## 手順の変更

既定は[lean参照](../../.claude/skills/pr-review/references/lean.md)。探索・反証・検証を同じコンテキストで行い、集計の母集団・単位、説明の各主張、変更に影響される別入口を確認する。「挙動が起きる」と「今回の仕様に反する」を別々に立証し、合成例は上流の写像まで追う。同名フィールドや意図した既定値から契約違反を推定しない。

第1版の出力を見た後、上記の仕様根拠と到達性を第2版へ加えた。第2版は#594の出力を見る前に固定。軽微なノイズは残るため、重要度と実害に基づく採点を続ける。文章と構成を同時に変えており、文言だけの効果は切り分けていない。

従来の[多エージェント手順](../../.claude/skills/pr-review/references/thorough.md)は比較記録として保持する。初回案の明示thorough選択は、全PRをleanで扱う決定に伴いスキルから削除した。最大2巡、CI待機、レビュー未完了の明示を維持する。確定した重要指摘だけをインライン投稿し、軽微・既存・未確認は要約に集約する。未確認を `confirmed: true` として送らない。

今後のPRでは時間、使用量、採用された重要指摘、撤回、未完了を記録する。見落としはleanの改善と再評価に使う。利用上限でAPIへ切り替えたり追加使用を有効化したりしない。
