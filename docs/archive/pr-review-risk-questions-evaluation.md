## きっかけ

## 方法

- 対象は #723・#728・#730・#740。各 PR の head だけを含む clone を作り（後のコミットは含まない）、`origin/dev` を merge-base に置いた。依存は head の lockfile でインストールした。
- 各 PR を旧プロンプト（当時の `lean.md` と `SKILL.md`）と新プロンプトで 1 回ずつ、Fable 5.2 / high で再生した。計 8 回。投稿なし、子エージェントなし、CI と同じコマンドに制限。Linear issue と PR 本文は当時の内容を渡した（#740 は当時と同じく issue なし）。
- 新プロンプトのリスク質問は、ルールファイルと、対象 4 PR 以外で見つかった指摘から作った。対象 4 PR だけで見つかった種類（移行後の行と API の不整合、画面が示す事実、セッションの鮮度）はこの測定では質問に入れていない。
- 採点は全体レビューの指摘と照合し、新しい主張はコードで確かめた。

## 測定後の変更

測定で外れた 4 件に合わせて、次を足した。これを含む版の再生は「パターン一覧を入れた版の再生」にある。

- 「読み取り後の書き込み」に、成功を返したのに上書きされる・エラーを返したのに行が残る、は欠陥だという基準を明記した。
- 「既存の行に対する移行」「画面やメッセージが示す事実」の質問を足した。
- 認証ライブラリの既定値の例に、保存形式・セッションの鮮度・トークンの寿命を足した。
- 保護がないと報告する前に、テスト環境が保護を切っていないか本番設定で確かめる、を足した。

## 事故由来の行と台帳の手順を削った版の再生（2026-11-16）

Fable 5.2 向けのプロンプトガイドは、細かい手順の指定と、事故ごとに足した狭い条件の積み重ねを避け、足すだけでなく削って試すよう勧めている。`lean.md` から次を削り（2,512 語から 1,984 語）、同じ 4 PR を同じ条件で 1 回ずつ再生した。`SKILL.md` と `patterns.md` は変えていない。

- 「測定後の変更」で足した 5 点すべて（後勝ちを欠陥とする基準、「既存の行に対する移行」と「画面やメッセージが示す事実」の質問、認証ライブラリの既定値の例、better-auth の origin 検査の例）。最後の 1 点は「保護がないと報告する前に、テスト環境ではなくデプロイ時の設定で確かめる」の 1 文に一般化した。

## 限界

各条件 1 回で、ばらつきは測っていない。質問は同じ全体レビューの別の PR の指摘から作っており、パターン一覧は対象 PR の指摘も元に含む。どちらも独立した未知の PR での確認ではない。再生は CI の runner ではなく、ツール制限は指示によるもので、権限では強制していない（旧プロンプトの #740 は許可外の読み取りコマンドを数回使ったと自己申告した）。投稿、スレッド解決、2 巡目は測っていない。 検出役と検証役に分けた版も 1 回の測定で、workflow の `find` ジョブ、artifact の受け渡し、検出役が欠けたときに 1 人のレビューへ戻す分岐は CI で動かしていない（workflow を変える PR では action がレビューを省くため、マージ後の最初の deep の PR で確かめる）。
